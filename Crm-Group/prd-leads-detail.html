需求规格说明书 (PRD)

留资详情（三期） (admin-leads-detail.html)

2026-07-16 产品部 V3.0.0
页面整体布局：采用经典的“上-左-右”结构。顶部为客户全局身份与操作区；左侧固定为基础档案表单（25%宽度）；右侧为主工作区（75%宽度），通过多 Tab 承载跟进记录、留资溯源及转化资产数据，并支持基础信息修正、状态再次调整、关联账户修改等三期能力。
1. 客户头部与全局操作 (Header)
UI 元素 数据来源与取值 展示规则、交互方式与信息处理
头像与姓名 来源：客户填写的姓名。 处理：截取姓名首字母或首字作为头像（带底色），右侧大字号展示全名。
身份状态角标 来源：CRM 核心系统状态同步。 排列：紧跟姓名右侧。
取值：“已转化”(绿底) 或 “已入金”(金底)。未转化时不显示。
基础溯源字段 来源：系统自动生成与匹配。 包含三项，横向排列：
1. 线索ID：唯一识别码（如 ID: L-20231015-001）。
2. 归属销售：当前分配人员。
3. 创建时间：首次留资入库的精确时间。
业务标签组 来源：全局标签库（Tag Library）。 交互：
1. 展示已有标签，悬浮时显示“x”图标，点击即可解除该标签绑定。
2. 点击“+ 添加标签”唤起全局标签选择弹窗（Checkbox多选），确认后实时追加到头部区域。
快捷复制按钮 来源：当前线索 ID + 当前登录销售的专属追踪码拼接。 包含：“复制代理邀请链接” 与 “复制直客邀请链接”。
交互：点击触发浏览器剪贴板 API 复制链接，并在按钮旁弹出短暂的“复制成功” Toast 提示。用于销售通过微信/WhatsApp定向发送开户链接。
退回公海按钮 交互动作触发入口。 点击唤起【退回公海弹窗】。弹窗内包含防霸单警告（30天不可认领），及必填的“退回原因”多行文本框。点击确认后：解除当前归属，状态变为待分配，关闭详情页并退回列表。
2. 基础信息表单 (左侧固定区)
字段名称 数据来源与状态 交互方式、约束与信息处理
姓名 / 手机号 来源：官网表单/落地页。
状态：可编辑。		 交互：标准 Input 输入框。销售在核实后可手动更正。
电子邮箱 来源：首次留资邮箱。
状态：禁止编辑 (Disabled)。		 核心约束：邮箱作为系统判定同客合并的唯一标识（主键），在详情页必须置灰并禁用修改，UI 鼠标悬浮呈现 not-allowed 状态。
系统匹配代理 来源：系统基于手机号自动从 IB 库中匹配。状态：只读。 展示系统自动匹配的结果，右侧附带“手机号关联”的绿色 Badge 提示数据来源依据。
手动重绑代理 来源：人工搜索 IB 库。
状态：可交互搜索框。		 交互：当系统匹配错误或未匹配时，销售在此输入代理名称/邮箱进行模糊匹配，选中后覆盖该线索的归属代理逻辑。
咨询内容 来源：客户录入时填写的初始内容。
状态：可编辑。		 标准 Select 交互。枚举值包含：成为代理、活动咨询、开户咨询、个人交易、其他。销售可在详情页内修正客户最初填写的咨询内容，保存后按最新值生效。
信息来源 来源：客户录入时填写的初始内容。
状态：可编辑。		 标准 Select 交互。枚举值包含：官网访问、社交平台、客户推荐、线上活动、线下金融活动、金融资讯网站、其他渠道。销售可在详情页内修正客户录入时填写的信息来源，保存后按最新值生效。
查询渠道 来源：销售人工维护。
状态：可编辑下拉框。		 枚举值固定为：WhatsApp、Email、Zendesk、Telegram。用于记录销售当前主要通过哪个沟通渠道查询或承接该客户。
保存修改按钮 交互动作触发入口。 点击校验必填项，通过后通过 Ajax 提交更新左侧表单，按钮呈现 Loading 状态，成功后提示“保存成功”。
3. 动态跟进与业务流转 (右侧 Tabs)
Tab 视图 模块内容与数据来源 排列方式、计算与交互逻辑
跟进记录
(默认展示)		 1. 发布区：跟进内容文本框、状态下拉、下次跟进时间选择器、发布按钮。
2. 时间轴区：人工跟进日志与系统状态变更日志混合。 		排列方式：按发生时间倒序排列（最新发生的在最上方）。
交互逻辑：
1. 销售填写内容并点击发布后，新记录无刷新追加至时间轴顶部。
2. 若下拉更改了线索状态（如“转为无效”），系统不仅生成一条跟进记录，同时会自动触发线索全局状态变更。
3. 状态可再次修改：即便当前线索已经处于“已转化”或“无效线索”，销售仍可再次通过跟进状态下拉框调整为其他状态，系统需保留完整变更轨迹。
4. 信息处理：时间轴区分“人工记录”（显示销售姓名及内容）与“系统日志”（特殊底色，如“系统：已成功转化为客户”）。
变更记录 来源：系统底层审计日志 (Audit Log)。 排列方式：时间倒序排列。
信息处理：仅客观展示该线索的“公海进出记录”、“分配人员变更记录”、“热度变更”，无操作按钮。用于防推诿和数据追溯。
留资记录 来源：基于当前客户“唯一电子邮箱”在全渠道（如官网、展会、开户页）的多次提交历史。 排列方式：时间倒序排列的卡片列表。
信息处理：Tab 名称需展示数量，如 留资记录（3）。卡片头部展示“第 N 次留资”及时间。卡片内展示当时填写的联系电话、信息来源、咨询内容及备注。此 Tab 仅供查阅，不可编辑，用于销售分析客户的长期关注点。
转化成果 来源：CRM Core (客户、账户、资金数据库)。 计算方式：
1. 净入金 = 累计入金总额 - 累计出金总额。
2. 累计盈亏 = 该名下所有交易账户平仓盈亏之和。
交互方式：
1. 若线索已开户，展示资产数据看板，底部提供“查看完整客户画像”按钮，点击新开标签页跳转至 admin-client-detail.html。
2. 关联账户支持新增与修改：若系统未自动匹配到开户数据，提供输入框及绑定按钮；若已存在关联账户，也需提供“修改关联”入口，允许销售改绑为新的客户账户，并记录变更日志。
