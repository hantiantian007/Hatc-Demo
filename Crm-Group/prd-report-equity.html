风控与运营报表 PRD (净值报表)

全局交互与数据规范

1. 左右联动架构与数据权限控制

放弃传统的复杂下拉表单筛选，采用左右分栏联动设计：

  • 左侧关系树权限控制：展示内容严格受登录角色权限控制。
    • 管理员账号：可查看全平台完整的代理及直客树状层级。
    • 代理账号：左侧关系树顶部根节点为其本人，仅能查看自己及其旗下发展的各级下级代理与直客数据，无法越权查看其他团队信息。
  • 右侧数据联动显示：点击左侧关系树的任意节点（代理或直客）后，右侧数据面板必须实时联动更新。上方汇总卡片动态变更为“当前选中节点及其所有下级（伞下）”的资金汇总数据。
  • 右侧数据列表呈现：右侧表格取消嵌套展开，改为扁平化列表。表格第一行固定展示当前选中节点自身的数据，下方列表平铺展示该节点的直属下级。

2. 数据模式切换 (Mode Switcher)

报表统一支持在【实时数据】与【历史快照】间切换：

  • 实时数据模式下：时间选择器置灰不可用。展示文案变更为 实时统计 (本月1日至当前)。系统强制按本月维度聚合流水数据。
  • 历史快照模式下：必须选择时间范围（支持到天）。默认时间筛选条件为：昨日（Yesterday）。

3. 底层数据架构与获取逻辑

  • 触发机制 (被动刷新)：废弃自动推流，采用被动查询。仅在首次加载、切换节点、切换时间/模式、或手动点击「刷新数据」按钮时拉取数据，加载时需展示 Loading 遮罩。
  • 实时流水拼接 (Lambda架构)：实时模式下的流水型数据 = CRM 历史快照底座 (本月1日至昨日) + MT5 API 实时拉取的今日增量明细，并在后端内存相加。
  • 伞下宏观汇总：右侧顶部卡片的伞下汇总数据，必须利用每日凌晨定时任务算好的“昨日伞下快照总和” + “MT5 组级 API 获取的今日宏观增量”进行拼接，严禁实时遍历递归几千名伞下用户的明细。

4. 数据准确性兜底防线 (核心红线)

  • 强对账机制：每日生成快照时，必须通过绝对资金公式 (今日0点净值-昨日0点净值) - (昨日净入金) + 昨日信用变动 校验流水累加总额，若有尾差必须触发报警。
  • MT5 绝对时区：所有的定时任务触发、流水切片、前端时间筛选，必须 100% 强制采用 MT5 Server Time，忽略本地服务器或浏览器时区。
  • 强制重算入口：需在后端或隐藏页面提供“强制重新同步指定月份数据”的 API/按钮，用于应对 MT5 管理员手动修改历史订单导致的数据不一致问题。

净值报表 (Equity Report)

查看原型

业务目标：核心风控与资产监控页面，用于实时查看伞下代理及客户的账户资产状况、净值结余及持仓盈亏表现。

核心字段与计算公式

页面显示字段 数据来源 定义与计算方式 (遵循 MT5 标准)
账号/名称 CRM 账户系统 MT5 交易账号及其在 CRM 中绑定的客户/代理真实姓名。
净值 (Equity) MT5 API 账户当前的绝对清算价值。
计算公式：结余 + 信用 + 浮动盈亏 + 过夜利息 + 手续费 + 佣金。
结余 (Balance) MT5 API 账户的实际可用现金余额（已结平仓盈亏，但不含未平仓浮动数据与信用赠金）。
信用 (Credit) MT5 API 账户当前拥有的信用额度（通常为入金赠金、信用补点等）。
佣金 (Commission) MT5 API 当前未平仓订单所产生的代理佣金总计。
手续费 (Fee) MT5 API 当前未平仓订单所产生的平台交易手续费总计。
过夜利息 (Swap) MT5 API 当前未平仓订单因跨日持仓而产生的隔夜利息总和（可正可负）。
浮动盈亏 (Profit) MT5 API 当前所有未平仓订单基于实时市场行情的纯价格波动盈亏总和（不含手续费与库存费）。

核心测试用例 (QA Test Cases)

以下用例覆盖了 P0/P1 级别的绝对红线场景，测试团队必须确保所有场景通过。

模块一：关系树与数据权限控制 (P0 - 绝对红线)
用例 ID 测试场景 前置条件 & 操作步骤 预期结果
AUTH-01 代理权限越权隔离 登录普通代理(节点A) -> 尝试通过 URL 或接口强行请求平行代理(节点B)数据。 任何试图获取非伞下节点数据的 API 请求必须返回 403，绝不能发生越权泄漏。
AUTH-02 左右联动与下钻 点击左侧关系树的某个“下级代理X”。 汇总卡片变为X的伞下汇总；列表第一行是X本人；下方列表仅展示X的直属子级。
模块二：数据模式与时区校验 (P1)
用例 ID 测试场景 前置条件 & 操作步骤 预期结果
TIME-01 历史快照默认时间 进入净值报表 -> 切换至【历史快照】模式。 时间选择器默认值必须精确回显为 昨日 (Yesterday) 的日期。
TIME-02 MT5 绝对时区边界 本地电脑为北京时间 -> 在 MT5 Server Time 的 23:59:59 执行流水。 该流水必须严格按 MT5 的时间戳进行归属，不允许因本地电脑时区导致跨日错乱。
模块三：核心计算公式与防线校验 (P0 - 资金安全)
用例 ID 测试场景 前置条件 & 操作步骤 预期结果
CALC-01 净值公式绝对校验 选取包含所有资金字段的账户，比对 API 返回与页面展示。 页面净值必须绝对等于：结余 + 信用 + 浮动盈亏 + 过夜利息 + 手续费 + 佣金。
CALC-02 宏观汇总防超载 点击一个伞下拥有 >5000 人的大代理节点。 必须在 2 秒内响应。严禁触发遍历 5000 人的明细循环查询。
CALC-03 强对账报警防线 后端人为制造昨日入金的脏数据 -> 触发凌晨快照生成任务。 绝对资金公式校验失败，系统必须阻断或触发飞书/邮件报警。
