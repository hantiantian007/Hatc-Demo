【需求文档】留资消息提醒

返回需求看板

1. 需求目标

当 CRM 内出现新的客户留资、或留资在“分配/退回公海”状态发生流转时，在左侧菜单展示红色数量角标，提醒不同角色在自己职责范围内关注新增信息。本需求只做提醒与查看，不引入复杂处理闭环。

项 说明 口径
需求名称 留资消息提醒 属于系统提醒能力，服务于“客户留资”模块的状态流转（待分配 / 已分配 / 公海）。
适用范围 客户留资列表与左侧菜单。 公海对所有销售可见；主管可见所有状态。
提醒目标 让各角色看到“对自己有意义的新增”。 主管关注“新增待分配”；销售关注“新分配给我”与“公海新增”。

2. 角色与可见性队列

队列 数据条件 可见范围
待分配 status = unassigned 所有主管可见。
我的留资 status = assigned 且 owner_sales_id = 当前销售 仅被分配的销售可见。
公海 status = pool 所有销售可见。
主管全量视图 主管可查看全部状态（用于检索、复盘）。 主管拥有全量查看权限，但提醒只关注“新增待分配”。

3. 提醒展示规则

位置 展示规则 说明
二级菜单：客户留资 展示红底白字数字角标。 数量 0 不展示；1-99 显示真实数量；大于 99 显示 99+。
一级菜单：客户管理 展示其下所有子菜单角标数量汇总（如仅“客户留资”接入，则等于客户留资角标）。 避免用户不点开二级菜单导致遗漏。
主管视角 角标 = 新增待分配未读数量。 采用“进入列表清零”的未读模型；每个主管独立统计，互不影响。
销售视角 角标 = 新分配给我的未读数量 + 公海新增未读数量。 采用“进入列表清零”的未读模型，避免角标永远累积。

4. 统计口径与公式

角色/队列 统计公式（伪 SQL） 口径说明
主管：新增待分配 count(leads where status='unassigned' and created_at > last_seen_unassigned_at) 每个主管独立维护已读时间；避免多人协作下“谁看过影响别人”的问题。
销售：我的新分配 count(leads where status='assigned' and owner_sales_id = me and assigned_at > last_seen_my_assigned_at) 以 assigned_at 作为新旧判断基准，支持转派/重新分配也能产生“新增”。
销售：公海新增 count(leads where status='pool' and entered_pool_at > last_seen_pool_at) 包含“新建直接进入公海”与“超时退回公海”的新增。
销售：菜单角标总数 new_assigned_count + new_pool_count 销售侧只展示“新增提醒”，不展示“我的存量待跟进”。

5. 清零（已读）规则

角色 清零方式 说明
主管 进入“待分配”列表页即更新 last_seen_unassigned_at = now()。 进入页面即视为已读，无需逐条已读；仅统计未分配状态的新增。
销售：我的新分配 进入“我的留资”列表页即更新 last_seen_my_assigned_at = now()。 进入页面即视为已读，无需逐条已读。
销售：公海新增 进入“公海”列表页即更新 last_seen_pool_at = now()。 仅清零公海新增提醒，不影响“我的新分配”。

6. 字段与数据结构建议

字段 说明 备注
status 留资状态。 建议值：unassigned / assigned / pool / closed。
owner_sales_id 当前归属销售。 未分配或在公海可为空。
assigned_at 分配给销售的时间。 每次重新分配都更新，用于“新分配提醒”统计。
entered_pool_at 进入公海时间。 每次退回公海都更新，用于“公海新增提醒”统计。
last_followup_at 最近一次跟进时间。 用于判断“分配后一定时间无跟进则退回公海”。
admin_module_last_seen 按账号记录模块已读时间。 字段：admin_id、module_key（leads）、bucket_key（unassigned/my_assigned/pool）、last_seen_at。

7. 接口建议（最小实现）

接口 用途 返回/入参示例
获取菜单角标 左侧菜单初始化/刷新时获取当前账号的提醒数量。 返回示例：
{ "leads": { "role": "manager", "new_unassigned_count": 12, "badge_count": 12 } }
{ "leads": { "role": "sales", "new_assigned_count": 3, "new_pool_count": 2, "badge_count": 5 } }
更新已读时间 进入不同列表页时更新对应 bucket 的 last_seen。 入参示例：{ "module_key": "leads", "bucket_key": "unassigned" }
入参示例：{ "module_key": "leads", "bucket_key": "my_assigned" }
入参示例：{ "module_key": "leads", "bucket_key": "pool" }

8. 边界与一致性规则

场景 规则 说明
多主管并存 主管角标按各自账号已读时间独立计算。 同一批新增待分配，可能被多个主管同时看到，属于预期行为。
转派/重新分配 更新 owner_sales_id 与 assigned_at。 被转派到的新销售可产生“新分配提醒”。
退回公海 更新 status=pool 与 entered_pool_at。 全销售公海新增提醒增加。
时间口径 所有时间字段统一以 UTC 存储与比较。 前端展示再按业务时区转换。

9. 验收标准

用例 操作 期望结果
新留资进入待分配 新增一条留资，状态为 unassigned。 所有主管的“新增待分配未读”角标 +1；销售菜单角标不变。
主管分配给销售 主管将该留资分配给销售 S（更新 owner_sales_id、assigned_at）。 该留资不再属于待分配统计范围；销售 S 角标 +1（新分配）；其他销售不变。
主管进入待分配清零 任一主管打开“待分配”列表页。 last_seen_unassigned_at 更新；该主管的新增待分配未读清零；不影响其他主管。
销售进入我的留资清零 销售 S 打开“我的留资”列表页。 last_seen_my_assigned_at 更新；销售菜单角标按规则减少（至少 my_assigned 部分清零）。
超时退回公海 留资分配给销售一定时间且无跟进，自动退回公海（更新 status、entered_pool_at）。 全销售“公海新增”未读数量 +1；主管新增待分配未读不因此增加（除非重新变为待分配）。
进入公海清零 任意销售进入“公海”列表页。 last_seen_pool_at 更新；公海新增提醒清零。
