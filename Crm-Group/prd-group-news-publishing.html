当前问题的本质不是“运营不会编辑”，而是现有集团动态发布功能过度依赖自由富文本，导致图片比例、段落节奏、桌面端与移动端展示效果不稳定。后续所有沟通均以本方案文档为准继续迭代。

1. 需求背景
背景项 说明
业务场景 集团动态主要用于在后台创建内容，并在官网 Web 端详情页中展示给外部访客查看，官网本身为自适应页面。
当前问题 现有后台主要依赖富文本编辑器录入正文内容，图片、图注、段落节奏、内容结构均混在一个内容流中，导致官网详情页在不同屏幕和不同图片比例下展示不稳定。
问题表现 正文行宽过长、段落节奏不稳定、图片比例混乱、双图展示不可控、桌面端和移动端效果不一致，未发布内容还可能出现空白详情页。
本次目标 将集团动态发布方式从“自由富文本”升级为“结构化字段 + 正文块 + 图片模块 + 前端统一渲染”，提升内容录入可控性与官网展示稳定性。
2. 现状问题
问题类型 现状描述 影响
内容模型过粗 当前模型基本为标题、时间、封面、正文富文本，正文承担了全部内容结构。 运营容易将正文、图片、图注、特殊版式全部塞进一个富文本框，内容结构失控。
图片展示不可控 长方形图、正方形图、双图、多图没有统一展示规则。 官网详情页容易出现图片比例混乱、并排关系失衡、移动端展示挤压等问题。
前端渲染过于依赖原始 HTML 详情页容易直接输出富文本结果，缺少文章级渲染约束。 后台看起来可编辑，官网最终效果却不稳定，且难以做统一优化。
发布态处理不足 未发布、待发布、已下线等状态边界不清晰。 前台可能出现空标题、空正文、空白骨架页，影响官网体验。
3. 功能目标
目标项 目标说明 落地方式
后台录入可控 运营录入内容时，不再完全依赖一个大富文本框自由排版。 将文章拆为基础信息、封面与摘要、正文块、图片模块、预览与发布。
前端展示统一 官网详情页不再直接原样输出富文本结果，而是按结构化数据渲染。 标题、时间、摘要走结构化字段；正文与图片模块按类型统一渲染。
自适应稳定 同一篇内容在桌面端与移动端展示效果稳定，不因图片比例不同而失控。 为不同模块定义统一的内容容器宽度、展示比例、最大高度与移动端规则。
未发布空态可控 未发布内容前台不能出现空白详情骨架。 前台根据发布状态返回明确空态文案。
4. 页面结构
区域 功能说明 备注
基础信息 标题、发布时间、语言、排序、发布状态。 结构化字段，属于文章级配置。
封面与摘要 封面图、摘要/导语。 封面图建议 16:9；摘要可复用到 SEO 描述和分享摘要。
正文编辑 承接连续阅读的文字内容。 仅保留基础富文本能力，不承接复杂图片拼版。
内容模块 承接图片与特殊结构。 首期支持：正文块、单图模块、双图模块、轮播模块。
官网预览 查看官网桌面端与移动端展示效果。 用于确认标题换行、图片比例、段落节奏是否合理。
5. 默认落地方案
方案 定义 结论
纯富文本 正文、图片、图注全部混在一个富文本内容流里。 不建议作为官网主方案，过度依赖运营手工排版。
正文 + 图片模块 正文负责叙述，图片与特殊结构交给模块。 默认落地方案，最适合当前集团动态场景。
全模块化 整篇内容拆成多个模块配置，不依赖长富文本。 展示最稳定，但后台配置过重，暂不作为首期默认方案。
6. MVP 范围
范围项 本期内容
后台录入 提供基础信息、封面与摘要、正文编辑、内容模块、官网预览五个核心区域。
结构化字段 支持标题、发布时间、语言、排序、发布状态、封面图、摘要。
模块类型 首期支持正文块、单图模块、双图模块、轮播模块。
模块交互 支持新增模块、展示模块列表、按顺序渲染；如研发排期允许，建议同步支持上移、下移、删除、编辑。
官网详情页 支持标题、时间、摘要的结构化渲染，以及正文块、单图、双图、轮播的统一模板渲染。
响应式 支持官网桌面端与移动端统一规则适配，重点保证双图与轮播在窄屏下的稳定性。
发布态控制 支持草稿、待发布、已发布、已下线，未发布状态下前台必须返回空态。
7. 非本期范围
事项 说明
全模块化文章编辑器 整篇文章全部拆成模块的重型方案，不作为首期目标。
复杂图文混排 如瀑布流、拼贴图、任意拖拽排版、复杂多列图文布局，不作为首期支持内容。
视频、附件、引用等高级模块 后续如有明确场景可继续扩展，本期不纳入。
后台所见即所得 100% 还原官网 本期只要求预览结果尽量接近官网，不要求后台编辑器与官网像素级一致。
8. 分期规划
阶段 目标 范围
一期 先解决集团官网动态“能稳定展示”的问题。 补基础字段、摘要、封面图规则、正文块、单图/双图/轮播模块、官网桌面端与移动端统一渲染、未发布空态。
二期 在一期稳定基础上，继续提升后台操作效率和内容扩展能力。 建议补模块拖拽排序、模块配置表单化、图库模块、图文模块、更多发布态管理、预览增强、列表页管理能力等。
9. 二期建议范围
方向 建议内容
后台交互优化 支持模块拖拽排序、展开/收起、删除确认、复制模块、模块配置实时回显。
模块扩展 新增图库模块、图文模块，支持 3 张及以上图片更稳定地承接，而不是全部交给轮播。
预览增强 后台支持更完整的官网预览，包括首屏、正文、图注、列表页卡片及分享卡片效果。
内容管理 补发布记录、版本留痕、草稿继续编辑、发布时间控制、列表筛选与搜索等后台能力。
前台体验 补上一篇/下一篇、相关推荐、分享能力、多图查看体验增强等内容消费能力。
10. 图片模块类型
模块类型 用途 桌面端规则 移动端规则
单图模块 承接单张图片，适合长图、主图、正文后单图展示。 跟随内容容器宽度，居中显示，原比例展示，限制最大高度。 继续单列展示，限制最大高度，避免超长图片拖屏。
双图模块 承接两张强关联图片，适合正方形并排或统一比例展示。 两列并排，同一展示比例裁切，禁止一大一小。 默认自动堆叠为单列，避免窄屏下继续并排。
轮播模块 承接多张图片，适合活动现场多图展示。 内容容器宽度内轮播，统一展示比例。 单列轮播，保持统一比例，不变形。
11. 字段定义
字段 类型 是否必填 说明
title string 是 文章标题。
publishTime datetime 是 发布时间。
language string 是 语言版本，建议支持 `zh-CN`、`zh-TW`、`en`。
sort number 是 官网列表排序值。
status string 是 发布状态，建议支持 `draft`、`scheduled`、`published`、`offline`。
coverImage object 是 封面图，推荐 16:9，建议尺寸 1200 x 675。
summary string 是 摘要/导语，详情页首屏展示，同时可复用到 SEO 与分享摘要。
blocks array 是 内容块数组，按顺序渲染。
12. 内容块定义
块类型 字段 是否必填 说明
paragraph content 是 正文内容，仅允许基础富文本能力。
single-image image / caption / displayRatio image 必填 单图模块；默认 `displayRatio = auto`，可选 `16:9 / 4:3 / 1:1`。
double-image images / caption / displayRatio / mobileStack images 与 displayRatio 必填 双图模块；`images` 固定 2 张，建议默认 `mobileStack = true`。
carousel images / caption / displayRatio / autoPlay / interval / showDots images 与 displayRatio 必填 轮播模块；建议至少 3 张图，首期支持左右切换 + 指示点即可。
13. 内容容器与尺寸规则
规则项 定义
内容容器宽度 文章正文真正排版的区域宽度。所有模块宽度都跟随内容容器，不允许单独自定义宽度。
桌面端 正文区域应设置最大阅读宽度，避免文字铺满屏幕。
移动端 正文区域为单列满宽减内边距，所有模块按单列优先适配。
单图模块尺寸 宽度跟随内容容器，按原比例展示，限制最大高度。
双图模块尺寸 必须选择展示比例，如 `1:1` / `4:3` / `16:9`；桌面端并排，移动端堆叠。
轮播模块尺寸 必须选择展示比例，如 `16:9` / `4:3`；桌面端与移动端统一比例缩放。
14. 前端渲染规则
渲染项 规则
标题/时间/摘要 走结构化字段，不从富文本中猜测。
正文块 按统一正文字号、行高、段间距渲染。
单图模块 按单图模板渲染，图片下方可选图注。
双图模块 按双图模板渲染，桌面端并排，移动端堆叠。
轮播模块 按轮播模板渲染，统一比例，不直接输出原图尺寸。
未发布状态 `draft / scheduled / offline` 前台显示明确空态，不显示空白详情骨架。
15. 校验规则
校验项 规则
标题、发布时间、封面图、摘要必须填写。 未填写时不允许提交发布。
至少存在 1 个正文块或内容块。 空内容不允许发布。
双图模块固定必须上传 2 张图。 少于或多于 2 张不允许保存。
轮播模块建议至少上传 3 张图。 少于 3 张给提示或限制保存，按研发评估决定。
双图模块与轮播模块必须选择展示比例。 无展示比例不允许保存。
封面图尺寸过低时提示。 低于推荐尺寸给出弱提示。
16. 验收标准
验收项 标准
后台录入 运营可完成标题、发布时间、语言、排序、发布状态、封面图、摘要、正文块与图片模块的录入。
模块使用 可新增正文块、单图模块、双图模块、轮播模块，并按顺序组织内容。
图片场景 可支持“正文后两张长方形图上下展示”“正文后两张正方形图桌面并排、移动端堆叠”等典型场景。
官网展示 同一篇文章在官网桌面端与移动端均正常展示，标题、摘要、图片比例与模块顺序正确。
发布态 未发布内容前台显示明确空态，不出现空标题、空日期、空正文骨架。
运营体验 运营不需要依靠空行、手工缩放图片、富文本拼图来修正最终页面效果。
17. 研发拆分建议
任务归属 建议拆分
后台任务 创建/编辑页改造、摘要字段、封面图规则、模块新增交互、模块顺序管理、后台预览。
前台任务 集团官网详情页结构化渲染、桌面端/移动端响应式适配、未发布空态、模块级模板实现。
接口任务 文章级字段与 blocks 数组结构定义、后台保存接口、前台详情查询接口、发布态透出。
联调任务 验证后台录入与前台展示顺序一致，验证长图/方图/轮播等典型场景渲染正确。
测试验收 覆盖发布态、桌面端、移动端、图片比例、摘要为空、模块为空、异常态降级等场景。
18. 研发注意事项
事项 说明
数据结构优先 优先统一文章级字段与 blocks 数组结构，不建议继续仅以富文本 HTML 为唯一数据来源。
顺序存储 正文块与模块必须共享统一顺序，避免正文在一个字段、图片在另一个字段后无法恢复真实展示顺序。
样式控制边界 运营端不提供任意图片宽高输入，不提供自由列布局；展示规则由前端组件固定控制。
移动端优先处理 双图模块与轮播模块必须先定义移动端规则，再定义桌面端规则，避免 PC 方案直接压缩到手机端。
富文本清洗 正文块仅允许基础富文本能力，建议过滤 Word 粘贴脏样式、任意字号颜色、手工图片尺寸样式。
空态与异常态 除正常发布态外，还需明确未发布、已下线、内容不存在、接口异常等前台降级展示策略。

20. 与研发沟通口径
这次集团动态功能不是单纯改样式，而是将发布方式从“纯富文本”升级为“文章级结构化字段 + 内容块数组”。 后台负责录入内容与模块配置，前端根据 `block.type` 做统一渲染，默认落地方案采用 正文 + 图片模块。
