需求规格说明书 (PRD)

首页统计数据逻辑修复 (支持自己及伞下数据)

2026-06-25 产品部 V1.2.1

1. 业务背景与核心原则

目前 CRM 首页的统计数据可能存在统计维度不一致、数据缺失或仅统计本人的情况，导致代理/IB 无法全面了解其整个团队的业绩和资金状况。为了提供更准确、更具商业价值的概览数据，本次需求将对首页所有核心指标的计算逻辑进行重构。

【最高原则】

首页所有的统计卡片、数据面板以及可视化图表，其数据统计口径必须统一变更为：
当前登录账户本人的数据 + 其整个团队（即伞下所有层级客户）的数据总和。
绝不允许遗漏间接下级客户的数据，必须实现全层级穿透计算。

2. 判定依据与数据范围 (唯一事实来源)

统计逻辑必须基于系统中客户层级树（关系树）的最新结构进行汇总。

  • 伞下客户定义：指由当前登录账号直接推荐，以及由其下级不断向下裂变产生的所有客户（无层级深度限制）。
  • 数据唯一事实来源：交易数据与余额等资金数据强依赖于 MT5 Server 的实时/定时快照数据；出入金与返佣数据依赖 CRM 财务流水记录。

3. 首页各项指标计算规则

下表详细列出了首页各个模块在修复前后的逻辑对比，研发请严格按照“修复后逻辑”实现。

功能模块 / 字段 原逻辑 (修复前) 修复后逻辑 (自己及伞下客户)
MT余额 / MT账号数 仅统计当前登录账户自己的 MT5 账户余额之和与账号数量。 统计本人名下 MT5 余额 + 伞下所有客户的 MT5 余额总和。
账号数 = 本人 MT 账号数 + 伞下所有客户 MT 账号数。
入 / 出金量 & 净入金 仅统计自己的充值、提现流水。 统计本人及伞下所有客户的成功入金、出金总和。
净入金 = (本人+伞下总入金) - (本人+伞下总出金)。
返佣金额 / 交易奖励 统计维度可能不全。 返佣金额：该账户因团队交易产生的返佣总和。
交易奖励：该账户及其团队触发的额外交易奖励总和。
未提现金额：该账户钱包中可提现但未提取的金额。
交易量 (Lot) / 盈亏 仅计算本人名下账号的平仓单手数及盈亏。 统计本人及伞下所有客户的历史平仓总手数 (Lot) 和总已结盈亏。
持仓量 (Lot) / 浮动盈亏 仅计算本人的未平仓单。 统计本人及伞下所有客户当前的未平仓总手数 (Lot) 及实时浮动盈亏汇总。
胜率分析 (环形图) 仅按本人历史平仓订单计算胜率。 将本人及伞下所有客户的历史平仓订单汇聚：
获利笔数 = 所有盈亏 > 0 的订单数。
亏损笔数 = 所有盈亏 <= 0 的订单数。
交易盈亏分析 (柱状/折线图) 仅展示本人每日/每月的盈亏走势。 图表时间轴上的每个数据点，代表当天/当月【本人+伞下所有客户】的平仓总盈亏。
