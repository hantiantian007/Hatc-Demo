【交付文档】官网行情模块前后端与测试说明

返回需求看板

本期重点

本需求目标是在官网新增一个“行情报价表”模块，用于展示外汇、贵金属、加密品种的实时参考行情。页面字段以 Symbol / Bid / Ask / Change / Change % / Sparkline 为主。

1
前端不能直接请求第三方行情源，必须由后端统一拉取、标准化、缓存后再对官网输出。
2
第一期建议采用 REST 轮询 + 后端缓存 方案，先保证稳定上线；第二期可升级为 WebSocket 持续接收。
3
所有对官网返回的字段名称、计算口径、错误码、延迟标记都以本文档为准，前后端不要直接依赖第三方原始字段。

1. 需求背景与适用范围

1. 官网需要新增一块“行情报价”区域，用于展示常见交易品种的实时参考价格，提升页面专业感与转化效率。

2. 本期仅做行情展示，不承接下单、开户、交易登录等行为。

3. 本期默认支持：EURUSD、GBPUSD、USDJPY、XAUUSD、XAGUSD、BTCUSD、ETHUSD。

4. 本文档以 Group-Gw 官网为承载对象，但接口设计允许后续复用到 Hk-Gw 或其他官网站点。

2. 数据源选型建议

项 建议 说明
首选方案 TraderMade 支持 Forex、Crypto、Precious Metals，且官方字段支持 bid、ask、mid，与官网行情表需求匹配度高。
一期接入方式 后端轮询第三方 REST 简单、稳定、可快速上线；配合后端缓存即可满足官网场景。
二期升级方式 后端订阅第三方 WebSocket 后端维护最新报价缓存，再继续对官网输出统一接口，不要求官网前端直接连 WebSocket。
不建议方案 官网前端直连第三方 会暴露 API Key，且后续无法做统一字段、缓存、限流、降级和供应商替换。

3. 总体架构

后端统一承接第三方行情接入、字段映射、缓存、涨跌计算、错误降级，对官网暴露标准化接口。

第三方行情源（TraderMade / 备用供应商）
            ↓
    官网行情后端服务
            ↓
  标准化 / 计算 / 缓存 / 降级
            ↓
       官网前端报价表

4. 品种配置规范

字段 示例 说明
symbol EURUSD 系统内部唯一标识，作为接口出参和缓存 key 使用。
display_name EUR/USD 官网展示名称，由后端统一返回，前端不要自己拼接。
category forex 枚举建议：forex / metal / crypto。
sort 1 列表排序值，由后端统一控制。
price_precision 5 价格展示精度。建议外汇 4~5 位，贵金属 2 位，加密 1~2 位。
建议维护一份后端配置，例如：
[
  { "symbol": "EURUSD", "display_name": "EUR/USD", "category": "forex", "sort": 1, "price_precision": 5 },
  { "symbol": "XAUUSD", "display_name": "XAU/USD", "category": "metal", "sort": 2, "price_precision": 2 },
  { "symbol": "BTCUSD", "display_name": "BTC/USD", "category": "crypto", "sort": 3, "price_precision": 1 }
]

5. 接口清单

接口 方法 用途
/api/market/quotes GET 获取官网行情报价列表，供行情表主区域使用。
/api/market/sparkline GET 获取单品种小趋势图数据；如果主接口已包含 sparkline，可先不单独实现。
/api/market/health GET 内部健康检查，可选；用于监控第三方行情拉取状态和缓存状态。

6. 主接口：报价列表

GET /api/market/quotes?symbols=EURUSD,XAUUSD,BTCUSD

当 symbols 为空时，后端按默认官网配置返回全部启用品种。

symbols 否 string 逗号分隔的品种代码列表。若不传，则返回默认官网品种列表。
site 否 string 站点标识，可选。若未来 Group-Gw 与 Hk-Gw 品种不同，可通过此参数区分。

7. 主接口字段定义

字段 类型 是否必返 说明
symbol string 是 品种代码，例如 EURUSD。
display_name string 是 官网展示名称，例如 EUR/USD。
category string 是 品种分类，用于前端样式或筛选。
bid number 是 买价。直接来自行情源或经过统一精度处理后的值。
ask number 是 卖价。直接来自行情源或经过统一精度处理后的值。
mid number 是 中间价，计算口径为 (bid + ask) / 2。
spread number 是 点差，计算口径为 ask - bid。
change number 是 涨跌额，基于约定基准价计算，详见第 9 节。
change_percent number 是 涨跌幅百分比，保留两位小数，数值本身不含 % 字符。
direction string 是 枚举：up / down / flat。
sparkline number[] 否 小趋势图数据，建议返回最近 5~20 个点即可。
updated_at string 是 该品种最近一次成功更新时间，UTC ISO8601 格式。
is_delayed boolean 是 是否为延迟数据。第三方拉取失败但命中缓存时返回 true。

8. 辅助接口：Sparkline

GET /api/market/sparkline?symbol=EURUSD&points=20

若前端主列表已经能从主接口拿到 sparkline，此接口可延后实现；但为了后续扩展资产详情页，建议预留。

{
  "success": true,
  "symbol": "EURUSD",
  "updated_at": "2026-07-29T10:30:25Z",
  "points": [
    { "t": "10:26:00", "v": 1.08390 },
    { "t": "10:27:00", "v": 1.08400 },
    { "t": "10:28:00", "v": 1.08410 },
    { "t": "10:29:00", "v": 1.08400 },
    { "t": "10:30:00", "v": 1.08420 }
  ]
}

9. 核心计算口径

字段 公式 / 口径 说明
mid (bid + ask) / 2 如果第三方已提供 mid，也建议后端统一自行计算，避免供应商口径差异。
spread ask - bid 前端只展示结果，不自行计算。
change latest_mid - baseline_price 一期建议 baseline_price 取“上一交易日收盘中间价”或“上一自然日 00:00 基准价”，由后端固定一种口径，不允许前后端混用。
change_percent (change / baseline_price) * 100 保留两位小数；前端再拼接 % 展示。
direction change 正负判断 > 0 为 up，< 0 为 down，等于 0 为 flat。

重要：后端必须统一定义 baseline_price 口径，并在一期内保持不变。否则同一品种在不同时间点返回的涨跌幅会出现不可解释的跳变。

10. 缓存与刷新策略

项 建议值 说明
第三方拉取频率 每 3 秒一次 满足官网展示即可，不追求交易级实时。
后端缓存 TTL 3~5 秒 避免前端并发请求直接打穿第三方接口。
前端请求频率 每 5 秒一次 由官网前端控制；后端无需强推。
Sparkline 点数 5~20 点 官网只需轻量趋势图，不建议返回长时间序列。

11. 错误处理与降级

场景 处理方式 说明
第三方接口短暂失败 返回上一次缓存 同时将 is_delayed 置为 true。
第三方长时间失败 返回业务错误码 若缓存也已失效，则返回失败状态，前端展示“行情暂不可用”。
单个 symbol 不存在 忽略该 symbol 或返回局部错误 建议一期采用“忽略非法 symbol + 返回有效数据”的宽容策略。
部分品种拿不到 sparkline 该字段可为空 主报价字段可用时，不应影响整条行情展示。
建议错误码：
{
  "success": false,
  "code": "MARKET_QUOTES_UNAVAILABLE",
  "message": "行情服务暂不可用，请稍后再试"
}

12. 安全与运维要求

项 要求
API Key 只能保存在后端环境变量或安全配置中，严禁下发到浏览器。
日志 记录第三方请求耗时、成功率、缓存命中率、错误码，但不要打印密钥。
限流 官网前端流量统一打到后端缓存，不直接打第三方；后端需防止突发流量重复拉取第三方。
监控 建议监控第三方请求失败率、缓存更新时间、返回延迟状态占比。

本期要做 本期不做

2. 完成报价列表接口。

5. 支持官网默认品种配置。 		1. 不做官网前端直连 WebSocket。

14. 后端验收标准

验收项 标准
接口可用性 默认品种列表可正常返回，字段名与本文档完全一致。
数值完整性 bid、ask、mid、spread、change、change_percent 均有值。
异常兜底 第三方短暂失败时仍能返回缓存，且 is_delayed = true。
安全性 前端和浏览器网络请求中看不到第三方 API Key。
可扩展性 后续新增品种或切换供应商，不要求前端改字段结构。

15. 前端对接说明

前端只消费本系统接口，不消费第三方接口；前端页面只负责展示、轮询、状态切换与轻量交互，不承接任何价格计算逻辑。

项 规则 说明
主列表接口 GET /api/market/quotes 行情表主区域统一请求该接口，不拆多个接口并发请求。
刷新频率 每 5 秒一次 建议使用固定轮询，不做高频抖动请求。
价格展示精度 以后端返回规则为准 前端不自行猜测品种精度；若需格式化，仅按后端配置渲染。
涨跌颜色 up 绿色，down 红色，flat 灰色 适用于 change、change_percent 与右侧 sparkline。
数值计算 前端禁止计算 mid、spread、change、change_percent 均以后端结果为准。
排序 按后端返回顺序展示 前端不自行按涨跌幅或名称重排，避免与业务配置不一致。
前端建议消费字段：
{
  "symbol": "EURUSD",
  "display_name": "EUR/USD",
  "bid": 1.08422,
  "ask": 1.08424,
  "change": 0.00043,
  "change_percent": 0.04,
  "direction": "up",
  "sparkline": [1.08390, 1.08400, 1.08410, 1.08400, 1.08420],
  "updated_at": "2026-07-29T10:30:25Z",
  "is_delayed": false
}

16. 前端状态与交互规范

状态 触发条件 页面表现
loading 页面首次加载且尚未返回数据 显示表格骨架屏或 loading 占位，避免直接闪空白。
normal 接口成功且 is_delayed = false 正常展示报价表。
delayed 接口成功但部分或全部行 is_delayed = true 报价表继续展示，同时在模块右上或底部轻提示“数据稍有延迟”。
empty 接口成功但 data = [] 展示空状态文案，例如“暂无行情数据”。
error 接口失败且无可用缓存 展示错误占位文案，例如“行情暂不可用，请稍后再试”。
前端交互要求：
项 要求
更新时间 可在模块底部展示“更新于 xx:xx:xx”，取主接口 server_time 或行级 updated_at。
百分点展示 change_percent 由前端拼接 %，数值正负号以后端结果为准。
趋势图 若 sparkline 为空，则展示占位线或隐藏该列图形，不影响其他字段展示。
响应式 移动端允许横向滚动或裁剪非核心列，但 Symbol / Bid / Ask / Change % 需优先保留。

17. 测试范围

测试模块 覆盖内容
接口测试 主接口、辅助接口、错误码、缓存命中、延迟标记、空数据返回。
前端联调测试 loading、normal、delayed、empty、error 五种状态展示是否正确。
数据正确性 mid、spread、change、change_percent 的计算口径是否与约定一致。
刷新与性能 前端 5 秒轮询下，页面不卡顿、不抖动；后端不会因多用户并发而重复高频打第三方。
安全性 浏览器网络面板不暴露第三方 API 域名密钥；接口返回不带第三方敏感字段。

18. 测试用例清单

编号 测试场景 预期结果
TC-01 首次进入页面，请求成功 先展示 loading，占位结束后展示报价表，字段完整无空列。
TC-02 默认品种列表请求 返回默认官网品种，顺序与后端配置一致。
TC-03 指定 symbols 请求 仅返回请求中的有效 symbols；非法 symbol 不导致接口整体失败。
TC-04 上涨数据展示 direction = up 时涨跌文字与折线均为绿色。
TC-05 下跌数据展示 direction = down 时涨跌文字与折线均为红色。
TC-06 持平数据展示 direction = flat 时涨跌文字为灰色，数值不出现异常正负号。
TC-07 第三方失败但缓存存在 接口继续返回缓存数据，且 is_delayed = true；页面展示“数据稍有延迟”。
TC-08 第三方失败且缓存失效 接口返回错误码 MARKET_QUOTES_UNAVAILABLE，页面展示错误占位。
TC-09 空数据场景 接口返回空数组时，页面展示“暂无行情数据”，不报错。
TC-10 sparkline 为空 不影响 Symbol、Bid、Ask、Change、Change % 展示，趋势图列可展示占位。
TC-11 精度检查 EURUSD、XAUUSD、BTCUSD 的展示精度符合后端配置，不出现前端擅自四舍五入导致的差异。
TC-12 浏览器安全检查 浏览器中只能看到本系统接口，不能看到第三方密钥或第三方请求地址。
