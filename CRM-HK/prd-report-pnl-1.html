风控与运营报表 PRD (盈亏报表)

业务模式：Mode B (直连 MT5)
目标用户：风控、市场、运营人员
更新日期：2026-07-02
状态：已评审
设计原则红线： 严格遵循“做减法”原则，取消所有冗余的配置型需求；在同页面内通过视图模式完成数据状态的切换，避免页面跳跃。

全局交互与数据规范

  • 数据模式切换 (Mode Switcher)：报表统一支持在【实时数据】与【历史快照】间切换。
    • 实时数据模式下：时间选择器置灰不可用。展示文案变更为 实时统计 (本月1日至当前)。系统强制按本月维度聚合流水数据。
    • 历史快照模式下：必须选择时间范围（支持到天）。
  • 左右联动架构 (Tree & Grid)：放弃传统的复杂下拉表单筛选，采用左右分栏联动设计。
    • 左侧关系树：展示完整的代理/直客层级架构，支持展开/折叠。
    • 右侧汇总卡片：点击左侧任意节点后，上方汇总卡片动态变更为“该节点及其所有下级（伞下）”的资金汇总数据。
    • 右侧数据列表：表格取消嵌套展开，改为扁平化列表。第一行固定展示当前选中节点，下方列表展示该节点的直属下级。
  • 底层数据架构与获取逻辑 (被动刷新与按需聚合)：
    • 触发机制：废弃自动推流，采用被动查询。仅在首次加载、切换节点、切换时间/模式、或手动点击「刷新数据」按钮时拉取数据，加载时需展示 Loading 遮罩。
    • 实时流水拼接 (Lambda架构)：实时模式下的流水型数据 = CRM 本地数据库固化的历史快照底座 (本月1日至昨日) + MT5 API 实时拉取的今日增量明细，并在后端内存相加。
    • 伞下宏观汇总：右侧顶部卡片的伞下汇总数据，必须利用每日凌晨定时任务算好的“昨日伞下快照总和” + “MT5 组级 API (Group API) 获取的今日宏观增量”进行拼接，严禁实时遍历递归几千名伞下用户的明细。
  • 数据准确性兜底防线 (核心红线)：
    • 强对账机制：每日生成快照时，必须通过绝对资金公式 (今日0点净值-昨日0点净值) - (昨日净入金) + 昨日信用变动 校验流水累加总额，若有尾差必须触发报警。
    • MT5 绝对时区：所有的定时任务触发、流水切片、前端时间筛选，必须 100% 强制采用 MT5 Server Time，忽略本地服务器或浏览器时区。
    • 强制重算入口：需在后端或隐藏页面提供“强制重新同步指定月份数据”的 API/按钮，用于应对 MT5 管理员手动修改历史订单导致的数据不一致问题。
  • 样式约束：数据表格的所有内容强制不换行（whitespace-nowrap），保持视觉整齐；货币和数值型数据统一右对齐，保留两位小数。

核心字段与计算公式

字段名称 数据来源与定义 实时获取与快照可行性评估
净值 MT5 账户核心指标。账户当前的清算价值（结余+信用+浮动盈亏）。 实时：极易。直接通过 MT5 API 读取 Account Summary。
快照：极易。系统每日 EOD (End of Day) 定时任务记录快照即可。
结余 MT5 账户核心指标。客户账户的实际现金余额（不含信用和浮动盈亏）。 实时：极易。同上。
快照：极易。同上。
浮动盈亏 MT5 实时持仓。该层级所有未平仓订单的实时盈亏总和。 实时：需通过 API 遍历该账号下所有 Open Positions 并累加盈亏，数据量大时有一定性能开销。
快照：易。按天汇总持仓快照即可。
信用 MT5 账户核心指标。账户中的赠金/信用额度。 实时：极易。直接通过 MT5 API 读取 Account Summary。
快照：极易。系统每日 EOD (End of Day) 定时任务记录快照即可。
平仓手数 MT5 历史订单。该层级所有已平仓订单的交易总手数。 实时：本地历史快照底座 + MT5今日实时增量拼接。
快照：易。
平仓笔数 MT5 历史订单。该层级所有已平仓订单的交易总笔数。 实时：本地历史快照底座 + MT5今日实时增量拼接。
快照：易。
手续费 MT5 历史订单。交易产生的手续费总和。 实时：同上，本地历史快照底座 + MT5今日实时增量拼接。
快照：易。
佣金 MT5 历史订单。交易产生的佣金总和。 实时：同上，本地历史快照底座 + MT5今日实时增量拼接。
快照：易。
过夜利息 MT5 订单。隔夜持仓产生的利息（含已平仓和未平仓）。 实时：未平仓查实时，已平仓采用本地快照+今日增量拼接。
快照：易。
平仓盈亏 MT5 历史订单。该层级所有已平仓订单的盈亏总和。 实时：采用本地历史快照底座 + MT5今日实时增量在后端拼接。严禁在查询接口中直接向 MT5 发起本月全量流水查询。
快照：易。按天计算增量并落库。
