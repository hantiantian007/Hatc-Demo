风控与运营报表 PRD (现实持仓报表)

业务模式：Mode B (直连 MT5)
目标用户：风控、市场、运营人员
更新日期：2026-07-02
状态：已评审
设计原则红线： 严格遵循“做减法”原则，取消所有冗余的配置型需求；在同页面内通过视图模式完成数据状态的切换，避免页面跳跃。

全局交互与数据规范

1. 纯实时数据 (Real-time Only)

本报表用于监控当前实时的风险敞口，仅提供实时数据，不设时间筛选器，不支持历史快照查询。

2. 极简筛选条件

本报表旨在宏观监控各交易品种的风险敞口，主列表不涉及微观账户层级的复杂查询。因此筛选条件极度精简：

  • 交易品种：下拉选择，默认“全部”，可选择特定品种（如 XAUUSD）。

3. 底层数据架构与获取逻辑

  • 触发机制 (被动刷新)：废弃 WebSocket 自动推流，采用被动查询。仅在首次加载、切换筛选条件、或手动点击「查询」按钮时拉取数据，加载时需展示 Loading 遮罩。
  • 直连持仓状态：报表数据直接反映 MT5 当前未平仓订单（Open Positions）的实时状态，无需拼接历史流水。

4. 数据准确性与性能防线 (核心红线)

  • 缓存与降级机制：考虑到主列表可能面临高频刷新，后端需对“品种宏观汇总”数据做秒级缓存；严禁每次请求直接穿透至 MT5 主服务器执行全盘扫描，以免造成 MT5 性能雪崩。
  • 明细查询下推：详情页的明细查询必须在 CRM 侧同步的本地订单库中完成，严禁直接使用 MT5 API 进行带条件的复杂关系树过滤查询。

现实持仓报表 (Real Position Report)

查看原型

业务目标：监控各交易品种在平台内的整体多空敞口方向，防止某一品种单边敞口过大带来的系统性赔付风险。报表分为【主列表：品种宏观汇总】与【详情页：品种持仓明细】两个层级。

1. 主列表：品种宏观汇总

默认展示全平台各交易品种的汇总数据，不支持下钻关系树，仅提供“交易品种”极简筛选。

  • 过滤空仓产品：列表仅显示当前有真实持仓的交易品种，当前无任何持仓的品种一律隐藏，不予展示。
  • 下钻详情交互：在表格中点击“交易品种”名称，即可跳转至该品种的【持仓明细页】，查看具体是哪些用户持有了该产品及其详细的交易订单信息。
UI 呈现表头 定义与公式
交易品种 按 MT5 Symbol 聚合（如 XAUUSD）。
净头寸(手) 买入总手数 - 卖出总手数。正数代表面临价格下跌风险，负数代表面临价格上涨风险。
浮动盈亏(USD) 该品种下当前所有未平仓订单的浮动盈亏总和。
笔数
BUY / SELL		 双行展示：上行为买单总笔数，下行为卖单总笔数。
买入 / 价格
手数 / 平均价		 双行展示：上行为 BUY 方向总手数，下行为 BUY 方向的持仓平均建仓价。
卖出 / 价格
手数 / 平均价		 双行展示：上行为 SELL 方向总手数，下行为 SELL 方向的持仓平均建仓价。

2. 详情页：交易品种持仓明细

在主列表中点击某一品种名称触发进入，展示构成该品种敞口的全部底层订单。顶部显示品种名称（如 XAUUSD）。

2.1 详情筛选条件

  • 基础搜索：MT 账号、账户名称。
  • 账号类型：下拉选择（全部、标准账号、美分账号）。
  • 多空方向：下拉选择（全部、BUY 多单、SELL 空单）。
  • 关系树：用于平台风控或大代理查看特定伞下团队的品种敞口。

2.2 列表核心字段说明

字段名称 说明
编号 前端展示序号，非 MT5 订单号。
MT 账号 & 账户名称 持仓所属客户的 MT5 账号及名称。
MT 账号类型 标签展示，区分“标准”与“美分”账户。
MT 账号净值(USD) 该账号当前的整体净值。
多空方向 订单交易方向：BUY 多 或 SELL 空，以不同颜色标签区分。
手数 该笔订单的持仓量（Volume）。
开仓均价 该笔订单的建仓价格（Price）。
浮动盈亏(USD) 该笔订单当前的实时未结盈亏，正数为绿，负数为红。
开仓时间 该笔订单的建立时间，格式：YYYY-MM-DD HH:mm:ss。

2.3 底部汇总栏指标

汇总指标 说明
持仓账号数 当前查询结果下，参与持仓该品种的去重后独立 MT 账号总数。
BUY/SELL 手数汇总 符合筛选条件的买/卖方向分别的总手数。
净头寸汇总(手) BUY 手数汇总 - SELL 手数汇总。
浮动盈亏汇总(USD) 当前结果集下所有订单的浮盈浮亏累加。
