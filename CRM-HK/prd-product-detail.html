C端商品详情页 (product-detail.html)

2026-07-01 产品部 V2.2.0
1. 页面内容与数据渲染
UI 模块 数据来源与获取 展示逻辑与排版要求
基础信息区 接口入参：URL 中的 ?id=xxx。
来源：后台商品基础配置。		 1. 顶部轮播图：最多支持 3 张，必须提供左右滑动与底部圆点指示器。
2. 标题与标签：标题下方展示商品类型（如“虚拟商品”）及“付费套餐”固定标识。
3. 商品介绍：直接渲染后台富文本编辑器录入的 HTML 内容，需确保内部图片的自适应（max-width: 100%）。
套餐选择卡片 来源：后台配置的该商品下的所有套餐数组。 卡片元素要求：
1. 套餐名称：如“基础版”、“进阶版”。
2. 价格展示：原价加删除线置灰，现价高亮加粗，并附带规格后缀（如 /月、/年）。
3. 库存状态：若库存充足则隐藏或显示具体数字；若为 0，需强制打上“已售罄”遮罩。
底部悬浮结算栏 数据随套餐选择实时联动。 1. 必须吸底悬浮展示 (fixed bottom-0)。
2. 左侧展示“应付总额”（跟随当前选中的套餐价格）。
3. 右侧展示“立即购买”主按钮。
2. 购买流转与资金校验 (支付确认弹窗)
流程节点 触发与动作 逻辑处理与防爆仓校验
唤起确认弹窗 点击底部“立即购买”按钮触发。 当前页面居中弹出 Modal 弹窗，不发生页面跳转。自动带入选中的“套餐名称”和“应付金额”。
加载 MT5 账号 弹窗初始化时自动拉取。 下拉框内列出当前用户所有状态正常的 MT5 交易账号，并拼接显示其实时可用余额 (Free Margin)，如“MT5 - 667788 (可用余额: $1,500.00)”。
资金校验 用户切换 MT5 账号时实时触发。 若 可用余额 < 应付金额，则触发拦截：
1. “确认购买”按钮置灰禁用。
2. 按钮文案变更为“余额不足，去入金”。
3. 点击该按钮跳转至入金页，并携带 ?redirect=当前详情页URL 以支持回跳。
提交与后续跳转 点击“确认购买”提交订单。 1. 按钮立即变为 Loading 状态锁定，防止网络延迟导致重复扣款。
2. 订单创建成功后，提示“支付成功，等待后台审核”。后台审核通过前，暂不实际扣除余额。
3. 延时 1.5 秒后，自动跳转至“我的订单页 (client-my-orders.html)”。
3. 逆向与异常流转处理
异常场景分类 触发条件与场景描述 前端处理方案与交互阻断
售罄套餐拦截 用户尝试点击或购买库存为 0 的套餐。 强阻断：
1. 若套餐卡片置灰，无法被设为 Active 选中状态。
2. 若用户默认进页时所有套餐均售罄，底部“立即购买”按钮强制变为“已售罄”并 Disabled。
参数丢失回退 用户直接通过书签或非法 URL 访问详情页，未携带 ?id=xxx。 强阻断跳转：进入页面后若检测到无 ID 参数，或接口返回该 ID 商品不存在/已下架，直接 Toast 提示“商品不存在或已下架”，并延时 1 秒后 history.back() 或跳转回商品列表页。
未登录拦截 未登录的 C 端散客通过官网导流进入该页面并点击购买。 授权拦截：点击购买时判断 Token，若无登录态，则弹出提示并跳转至 register.html 或 login.html。同时需将当前商品详情 URL 作为 redirect 参数存入，保证登录后原路返回继续购买。
