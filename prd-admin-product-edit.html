需求规格说明书 (PRD)

新增/编辑商品 (admin-product-edit.html)

2026-07-01 产品部 V1.1.0
1. 页面初始化与来源逻辑
入口场景 参数传递 处理逻辑与数据渲染
新增商品 无参数传递。 页面标题显示为“新增商品”。所有表单项均为空，仅保留 1 个空白的默认套餐卡片供填写。
编辑商品 URL 携带 id 参数。
例如：?id=PRD-001		 页面标题显示为“编辑商品”。
前端解析 URL 中的 ID，调用获取详情接口，将返回的商品名称、类型、简介、图片、图文详情以及所有关联套餐列表，完整回显在对应的表单控件中。
2. 基础信息与图片表单
字段名称 输入类型与限制 前端交互与数据处理规则
商品名称 单行文本，必填。
最多 50 字符。		 失焦时检查是否为空，若为空则在输入框下方红色提示“商品名称不能为空”。
商品类型 下拉单选框，必填。 枚举值：虚拟商品、实体商品。该字段将决定客户端展示的视觉标签。
商品简介 多行文本 (Textarea)，必填。
最多 100 字符。		 用于填写商品的一句话卖点或短描述。该内容将直接输出并展示在 C 端商品列表的卡片中。
支付方式 纯文本展示。 状态为 只读，固定显示“余额购买”，不可更改。
上架状态 单选框 (Radio)。 选项：立即上架、定时上架、暂入仓库。
联动交互：当且仅当选中“定时上架”时，下方动态展开一个精确到分钟的日期时间选择器 (Datetime picker) 供操作者设定生效时间。
列表展示图 图片上传组件，限制 1 张。 尺寸约束：比例必须严格约束为 2.4:1（建议尺寸 600x250 px）。
处理：上传时前端应进行长宽比校验并可提供裁剪工具，该图将作为商品在各端列表页的主视觉封面。
详情轮播图 图片上传组件，最多 3 张。 支持拖拽排序。这组图片将用于客户端商品详情页的顶部轮播图模块。
图文详情 富文本编辑器。 集成基础的图文排版能力（加粗、改色、插图），用于承载长篇详细介绍。
3. 多套餐配置与提交操作
操作/区块 数据结构 交互流转与信息处理
动态套餐卡片 JSON 数组形式。 卡片内字段：套餐名称、原价(选填)、优惠价(必填)、规格后缀(如“/月”)、库存数量(必填)。
增删交互：
1. 点击“+ 添加套餐”按钮，在列表末尾追加一个全新的空白套餐卡片。
2. 点击任一套餐卡片右上角的“删除”图标，移除该卡片。
约束条件：无论怎么删除，页面中至少必须保留 1 个套餐卡片。
取消按钮 路由跳转。 点击后，放弃当前所有修改，直接返回 admin-product-management.html。
保存商品按钮 表单提交与流转。 处理逻辑：
1. 拦截校验：点击时，前端遍历所有必填字段（包含所有未被删除的套餐卡片内部字段）。若有未填项，页面滚动至错误位置并高亮红框提示。
2. 提交与反馈：校验通过后，拼装数据对象发送至后端保存接口。按钮变为 Loading 状态。
3. 成功跳转：收到后端成功响应后，弹出“保存成功” Toast，延时 1 秒后跳转回 admin-product-management.html 列表页。
4. 逆向与异常流转处理
异常场景分类 触发条件与场景描述 前端处理方案与交互阻断
表单防丢与强退 表单内容发生过任何变动（Dirty 状态）后，用户点击浏览器“后退”或页面上的“取消”按钮。 二次确认阻断：拦截路由跳转，弹出确认框提示：“您有未保存的更改，确认要离开吗？未保存的内容将会丢失。”点击确认后方可离开。
库存超卖边界约束 操作人员在套餐库存输入非法字符（如负数、字母），或输入库存为 0。 输入约束：前端强制输入框只允许输入 >= 0 的正整数。
为零逻辑：允许保存库存为 0 的套餐。保存后，该套餐在客户端直接显示为“已售罄”，且“立即购买”按钮置灰不可点击。
图片上传异常 1. 列表展示图比例不是 2.4:1。
2. 单张图片体积超过 5MB。
3. 网络超时导致上传中断。 		比例与大小拦截：唤起前端裁剪工具强制按 2.4:1 比例框选。超出 5MB 则拦截上传并提示“图片大小不能超过 5MB”。
断网处理：若接口超时，图片预览区呈现红色占位并显示“重新上传”按钮供用户重试。
提交防重与防连击 因网络延迟卡顿，用户在表单填写完毕后，疯狂连续点击“保存商品”按钮。 Loading 锁死：点击一次“保存商品”后，按钮立刻进入 Loading 动画状态并添加 Disabled 属性，彻底阻断后续点击。直到接口返回明确结果（无论 200 还是 500），若失败则解除禁用并保留用户已填写的数据。
