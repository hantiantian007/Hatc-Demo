系统方案：美分账户接入与全链路改造

更新: 2026-07-30 面向: 产品 / 研发 / 测试 状态: 方案版
文档目标： 本文档用于统一美分账户需求的业务口径、研发改造边界、测试验收标准，并给出研发成本与排期建议，供产品、研发、测试同步评估。

0. 一句话结论

美分账户不是简单增加一个账户名称，而是新增一种常规账户类型。它将影响开户、账户展示、资金流转、客户资产汇总、活动与提成、报表导出等整条链路。

本次改造的核心不是页面加一个“美分账户”选项，而是让系统具备按账户单位识别金额，并统一按美元口径做汇总计算的能力。

1. 需求背景与目标

业务希望平台支持美分账户，且面向所有用户开放，不区分新用户和老用户。

美分账户与标准账户共享现有交易规则、审核规则、产品范围与活动范围，仅在金额单位与MT 分组上存在差异。

因此，本次需求目标为：

  • 支持用户在开户或增开账户时自行选择标准账户或美分账户；
  • 支持同一用户同时拥有多个标准账户和多个美分账户；
  • 支持标准账户与美分账户之间的内转，并按固定比例自动换算；
  • 支持前后台对美分账户金额进行双展示；
  • 确保客户资产、活动、返佣、提成、报表汇总全部统一按美元口径计算。

2. 已确认业务规则

规则项 确认结果 业务口径
适用人群 全量用户开放 不区分新用户和老用户，美分账户属于平台常规账户类型。
账户关系 可同时拥有 同一用户可同时持有标准账户和美分账户。
美分账户数量 不限数量 用户可开多个美分账户，不设数量上限。
开户方式 用户自行选择 客户在开户或增开账户时，前台可直接选择标准账户或美分账户。
MT 分组 独立分组 美分账户使用独立 MT 分组，与标准账户明确分开。
资金规则 与标准账户一致 入金、出金、信用金、赠金规则与标准账户完全一致。
产品与活动支持 全部支持 现有产品、活动、返佣、提成均支持美分账户参与。
账户转换 不允许直接转换 已有标准账户不可直接改为美分账户，只能新开美分账户。
内转规则 允许并自动换算 标准账户和美分账户之间允许内转，系统自动按固定比例换算。
换算比例 固定 1:100 统一按 1 USD = 100 USC 处理，不做动态比例。
金额展示 前后台都双展示 前台和后台都同时展示原始金额与折算后的美元金额。
汇总口径 统一按美元 活动、返佣、提成、客户总资产、报表汇总统一按美元口径统计。
交易与审核参数 与标准账户一致 杠杆、最小手数、交易品种、审核流程均与标准账户保持一致。

3. 产品方案

3.1 产品原则

1. 单账号页面展示原始金额 + 折算美元金额。

2. 跨账号汇总、活动门槛、返佣提成、客户总资产、报表统计统一按折算美元金额计算。

3. 美分账户与标准账户同权，仅金额单位不同，不在产品能力上做额外削减。

3.2 影响模块

模块 产品调整点 说明
开户 / 增开账户 新增账户类型选择 用户可在开户时选择“标准账户 / 美分账户”。
客户详情 / 账户列表 增加账户类型、单位、双金额展示 需区分标准账户和美分账户，并展示原始金额与折算金额。
入金 / 出金 / 内转 支持双单位和换算逻辑 标准户与美分户内转时自动按 1:100 换算。
客户资产汇总 统一按美元口径汇总 客户名下多账户统一换算后再统计总资产。
活动 / 返佣 / 提成 统一按美元口径判断门槛和发放基数 避免美分账户因原始金额放大 100 倍导致口径失真。
报表 / 导出 增加账户类型和双金额字段 导出文件必须明确单位和折算值，避免误读。

3.3 前后台展示口径

示例：
账户类型：美分账户
原始余额：10,000.00 USC
折算余额：100.00 USD

无论前台还是后台，均建议明确展示金额单位，避免运营、财务、客户误将 USC 理解为 USD。

4. 研发改造方案

4.1 研发核心原则

  • 账户的原始金额与标准金额必须同时保留。
  • 所有汇总型逻辑必须以标准金额（USD）为准。
  • 前端禁止自行换算金额，统一由后端输出原始金额、折算金额与单位。
  • 内转需保留转出原始金额、转入原始金额、换算比例、折算美元金额，便于对账。

4.2 建议新增字段

对象 字段 说明
账户表 account_mode 账户模式：standard / cent。
账户表 currency_unit 金额单位：USD / USC。
账户表 amount_scale 换算倍数：标准账户 1，美分账户 100。
账户表 mt_group 当前 MT 分组，美分账户需进入独立分组。
流水 / 报表明细表 original_amount MT 原始金额。
流水 / 报表明细表 normalized_amount_usd 统一折算后的美元金额。
流水 / 报表明细表 conversion_ratio 换算比例，固定记录为 1:100。
流水 / 报表明细表 original_currency_unit 原始单位，防止后续导出时丢失语义。

4.3 核心公式

标准账户：normalized_amount_usd = original_amount
美分账户：normalized_amount_usd = original_amount / 100

spread / 净入金 / 客户总资产 / 活动门槛 / 提成基数 / 报表汇总
=> 全部使用 normalized_amount_usd

4.4 重点改造模块

模块 研发改造点 风险说明
开户服务 新增账户模式参数，开户后写入独立 MT 分组。 若分组映射错误，会导致账户类型识别错误。
账户管理 账户列表和详情统一输出原始金额、折算金额、单位。 前后端若字段未统一，容易出现展示口径不一致。
资金服务 入金、出金、内转记录增加换算逻辑与双金额字段。 标准户与美分户互转是本次最容易出错的环节。
客户资产汇总 按账户汇总前先统一折算为美元。 否则客户资产会被放大 100 倍。
返佣 / 提成服务 所有提成基数统一切到美元口径。 若仍使用原始金额，发钱会严重失真。
报表 / 导出服务 新增账户类型、原始金额、折算金额、单位列。 若导出不带单位，财务和运营会误读数据。

4.5 明确不做

  • 不支持把已有标准账户直接改造成美分账户；
  • 不引入动态换算比例或后台可配置倍率；
  • 不为美分账户单独制定新的杠杆、手数、审核、活动规则。

5. 测试方案与验收标准

5.1 测试范围

  • 开户与增开账户流程；
  • 账户列表 / 客户详情的双金额展示；
  • 标准账户与美分账户之间的内转换算；
  • 客户总资产、活动门槛、返佣、提成的美元汇总；
  • 报表、导出与对账口径；
  • 异常与边界场景：多个美分账户、多账户混合、历史数据兼容。

5.2 核心测试用例

编号 测试场景 预期结果
TC-01 用户新开美分账户 开户成功，账户类型为美分账户，分组落到美分分组。
TC-02 老用户增开美分账户 允许成功增开，不因老用户身份被限制。
TC-03 同一用户同时持有多个美分账户 客户详情和账户列表正常展示，不因数量限制报错。
TC-04 标准账户转 100 USD 到美分账户 转出记录为 100 USD，转入记录为 10,000 USC，折算金额均为 100 USD。
TC-05 美分账户转 10,000 USC 到标准账户 转出记录为 10,000 USC，转入记录为 100 USD，折算金额一致。
TC-06 客户总资产汇总 标准账户和美分账户统一折算后汇总，结果按美元口径正确。
TC-07 活动门槛判断 活动、返佣、提成统一按折算后的美元金额判断，不按原始金额判断。
TC-08 前后台双展示 所有相关页面均展示原始金额、折算金额和金额单位。
TC-09 导出文件校验 导出中包含账户类型、原始金额、折算金额、单位字段。
TC-10 尝试直接转换已有标准账户 系统明确拒绝，不支持直接转换。

5.3 测试验收标准

  • 不存在任何因美分账户原始金额放大导致的客户资产、提成、报表口径错误；
  • 标准户与美分户互转在页面展示、流水记录、报表汇总三处结果一致；
  • 所有跨账户汇总场景均按美元口径输出；
  • 前后台与导出文件的字段语义完全一致。

6. 风险点

风险点 风险描述 建议
金额放大 100 倍 若有模块继续使用原始金额做汇总，会导致客户资产、提成、活动判断错误。 统一下沉到服务端做标准金额换算，不允许前端自算。
内转换算错误 标准户和美分户互转时，若转入转出记录不一致，会直接影响对账。 资金流水中同时保留原始金额、折算金额和换算比例。
导出误读 若报表和导出缺少单位字段，财务容易把 USC 当成 USD。 导出强制带单位和折算字段。
历史兼容 老数据若未补足账户单位，可能导致部分统计无法准确追溯。 上线前确认是否需要对历史账户补标识。

7. 研发成本与周期评估

本次需求应定义为中高成本的账户体系改造，而不是简单的页面新增需求。

原因在于：美分账户会穿透到账户、资金、报表、活动、返佣提成、导出等多模块，且允许标准户与美分户互转，这会显著提升改造复杂度。

评估项 结论 说明
研发成本 中高 不是单点功能，而是账户体系和金额口径的链路级调整。
合理周期 4 - 8 周 视现有资金、报表、提成模块耦合程度而定。
建议预估 约 6 周 作为正式排期时更稳妥的评估值。
排期建议 建议分两期 先完成账户与资金主链路，再完成报表、提成、导出等扩展链路。

7.1 建议排期

阶段 建议周期 内容
第一期 3 - 4 周 账户类型、开户 / 增开、MT 分组、账户展示、入金 / 出金 / 内转、客户总资产美元汇总。
第二期 2 - 4 周 活动、返佣、提成、报表、导出、回归测试与历史兼容处理。

8. 剩余待确认实施细节

当前大方向已经明确，剩余建议补充确认的内容主要用于提升实施细节完整度：

  • 前台和后台对于“美分账户”的正式命名文案；
  • 导出文件是否固定增加“账户类型 / 原始金额 / 折算金额 / 单位”四列；
  • 内转流水是否需要额外展示换算比例与换算前后金额；
  • 是否需要为美分账户的开立与互转单独记录审计日志。

备注：本文档已按当前已确认业务规则整理；若后续业务规则变更，应以“汇总统一按美元口径”作为不可变的底层约束。
